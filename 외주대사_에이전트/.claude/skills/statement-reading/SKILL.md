# 거래명세서 판독 규칙

명세서 판독 결과는 대사의 **기준값**이다. 여기서 틀리면 대사 전체가 틀린다. 속도보다 정확도가 우선이다.

## 1. 읽는 순서
1. 첫 페이지 상단에서 **공급자 상호·사업자번호**를 읽고 `config/업체마스터.csv`의 업체와 일치하는지 확인한다. 다르면 멈추고 사용자에게 알린다.
2. **거래기간**이 마감월과 맞는지 확인한다. 다르면 사용자에게 알린다.
3. 표 머리글을 읽어 각 칸이 무엇인지 확인한다. 업체마다 칸 이름이 다르다(예: `품번` 대신 `품목코드`).
4. 페이지 하단의 페이지 번호(예: 1 / 2)로 전체 장수를 확인하고, **모든 페이지**를 읽는다.
5. 표의 행을 위에서 아래로 한 줄씩 옮긴다. 빈 행은 건너뛴다.
6. 마지막 페이지의 **공급가액 합계, 세액 합계, 합계금액**을 읽는다.

## 2. 칸별 기재 규칙

| 컬럼 | 규칙 |
|---|---|
| 업체코드 | 업체마스터의 코드 (V001 …) |
| 파일명 | PDF 파일명 그대로 (예: 대성정밀_거래명세서_202609.pdf) |
| 페이지 | 그 행이 있는 PDF 페이지 번호 (1부터) |
| 순번 | 명세서 No 칸에 **인쇄된 숫자 그대로**. 순번 칸이 없으면 문서 전체에 위에서부터 1, 2, 3… 매기고 `순번표기=줄위치` |
| 납품일자 | `YYYY-MM-DD`. `09/01`처럼 연도가 없으면 거래기간의 연도를 붙인다. 월·일이 두 칸이면 합친다. 날짜가 머리글에만 있는 납품건별 명세서는 그 장의 모든 행에 같은 날짜 |
| 발주번호 | 영문 대문자·숫자·하이픈 그대로. `O`(오)와 `0`(영), `I`와 `1` 혼동 주의 — 같은 명세서의 다른 행과 형식을 비교한다. **양식에 칸이 없으면 빈칸** |
| 품번 | 위와 동일. 같은 품명은 보통 같은 품번이므로 행끼리 교차확인한다 |
| 품명 | 보이는 그대로 |
| 수량·단가·공급가액·세액 | 쉼표 없이 정수. 반품 표기(`△6`, `▲6`, `(6)`, 빨간 글씨, `-6`)는 모두 음수 `-6`. 단가는 양수 그대로. 라인 세액 칸이 없는 양식은 세액 **빈칸** |
| 비고 | 명세서 비고 칸 내용 + 판독 메모 |
| 수기정정 | 펜으로 고친 흔적이 있으면 `Y`, 아니면 `N` |
| 판독확신도 | `상`(확실) / `중`(흐리지만 교차확인으로 확정) / `하`(확정 불가) |
| 명세서번호 | 납품건별로 장마다 번호가 있는 명세서면 그 번호(예: HS-2609-026). 월합계 명세서는 빈칸 |
| 순번표기 | `인쇄`(명세서에 No 칸이 있음) / `줄위치`(No 칸이 없어 위에서부터 셈) |

품번 칸 이름은 업체마다 다르다: `품번`, `품목코드`, `도면번호`, `Part No.` 모두 품번 칸이다. `규격`(재질·두께 등)은 품번이 아니므로 비고에 남긴다.

## 3. 숫자 교차확인 (행마다)
- **수량 × 단가 = 공급가액** 인지 확인한다. 안 맞으면 세 숫자를 다시 본다.
  - 다시 봐도 안 맞으면 명세서 그대로 적고 비고에 `수량×단가≠공급가액(명세서 원문)`.
- 세액은 공급가액의 10% 근처(±1원)여야 한다. 업체별로 반올림/절사가 다를 수 있으니 1원 차이는 정상이다.
- 6과 8, 3과 8, 1과 7, 0과 6 은 스캔에서 자주 헷갈린다. 의심되면 교차확인 결과를 우선한다.

## 4. 수기정정(펜 글씨) 처리
- 인쇄된 숫자에 줄이 그어져 있고 옆이나 위에 손글씨 숫자가 있으면 **손글씨(정정값)를 채택**한다.
- `수기정정=Y`, 비고에 `인쇄 62 → 수기 60` 형식으로 둘 다 남긴다.
- 정정값으로 `수량×단가=공급가액`이 맞는지 확인한다(보통 인쇄 금액이 정정값 기준으로 되어 있다).
- 정정 옆에 업체 날인/서명이 없으면 비고에 `정정날인 없음`을 덧붙인다.

## 5. 합계 JSON
`work/<월>/추출/<업체코드>_명세서합계.json`
```json
{
  "업체코드": "V001",
  "업체명": "(주)대성정밀",
  "파일명": "대성정밀_거래명세서_202609.pdf",
  "거래기간": "2026-09-01~2026-09-30",
  "페이지수": 2,
  "라인수": 20,
  "공급가액합계": 10750000,
  "세액합계": 1075000,
  "합계금액": 11825000
}
```
- 값은 **하단에 인쇄된 숫자**를 적는다. 네가 더한 값이 아니다. (그래야 검증 스크립트가 판독 오류를 잡는다.)
- `라인수`는 판독한 총 행수.
- 라인별 세액이 없는 양식이면 `세액합계`는 하단에 인쇄된 부가세를 적는다.
- **납품건별 명세서**(장마다 합계가 있고 월 합계가 없음)는 장별 합계를 아래처럼 함께 적는다. 전체 합계는 장별 합계를 더한 값이며 `비고`에 그렇게 남긴다.
```json
"명세서별합계": [
  {"명세서번호": "HS-2609-014", "페이지": 1, "공급가액": 412000, "세액": 41200},
  {"명세서번호": "HS-2609-017", "페이지": 2, "공급가액": 286500, "세액": 28650}
]
```
검증 스크립트가 장별로도 맞춰보므로, 어느 장에서 판독이 틀렸는지 바로 드러난다.

## 6. 작업 습관
- 한 업체를 끝낼 때마다 바로 CSV를 저장한다. 여러 업체를 머릿속에 들고 있다가 한꺼번에 쓰지 않는다.
- 판독이 끝나면 반드시 `python scripts/validate_extraction.py --month <월>` 을 돌린다.
- 이미지가 흐리면 추측하지 말고 `python scripts/pdf_to_images.py --month <월> --file <파일명> --dpi 300` 으로 다시 변환해서 본다.
