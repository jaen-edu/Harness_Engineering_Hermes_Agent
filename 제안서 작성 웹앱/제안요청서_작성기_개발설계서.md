## 1. 개요

### 1.1 목적
구매요청이 들어올 때마다 협력사별 제안요청서(RFQ)를 손으로 작성하는 작업을 없앤다. 구매요청서 엑셀을 올리면 양식 워드에 맞춰 **구매요청 건별 × 협력사별** 제안요청서가 자동으로 만들어지고, 목록에서 바로 내려받을 수 있게 한다.

### 1.2 플랫폼 선정 근거
요구사항초안의 판정 기준에 따라 엑셀을 읽고, 워드 파일을 만들고, 다운로드 버튼이 있으므로 **Python + Streamlit(실행.bat 포함)**으로 개발한다.

### 1.3 범위
| 포함 | 제외 |
|---|---|
| 구매요청서 업로드·검증 | 메일 자동 발송 |
| 품목군 기준 협력사 자동 매칭 | 견적 회신 비교·분석 |
| 대상 건 체크박스 선택/제외 | 구매요청서 "상태" 값 자동 변경 |
| 협력사별 .docx 생성 | 작업 이력 저장 (요구사항: 기억 안 함) |
| 개별 다운로드 + ZIP 일괄 다운로드 | PDF 변환, 공휴일 자동 반영 |

## 2. 확정 요구사항 (질의 결과)

| # | 항목 | 결정 내용 |
|---|---|---|
| 1 | 요청번호 규칙 | `RFQ-` + PR번호 뒷부분 + `-` + 협력사명 → 예: `RFQ-2610-001-서진금속` |
| 2 | 회신 기한 | 작성일 + **3영업일**(토·일 제외), **17:00**, 요일 표기 → 예: `2026-10-21(수) 17:00` |
| 3 | 요청일 | 앱에서 생성하는 **당일 날짜** (화면에서 변경 가능) |
| 4 | 한 협력사·여러 품목 | **구매요청 건별로 따로** 작성 (경동스틸 → 봉재 1장, 판재 1장) |
| 5 | 안내 문구 | 양식 문구 **그대로** 사용 (품목군별 변경 없음) |
| 6 | 협력사 비고 | 요청서에는 넣지 않고 **화면에만 표시** |
| 7 | 대상 선택 | 상태가 `요청서 발송 전`인 건만 대상, 화면에서 **체크 해제로 제외** 가능 |
| 8 | 출력 형식 | **.docx만**, 개별 다운로드 + **ZIP 일괄 다운로드** |
| 9 | 발신자 | 양식에 적힌 `한빛정밀㈜ 구매팀 김하늘 대리 (…)` **그대로 유지** |

## 5. 처리 로직

### 5.1 전체 흐름
```
구매요청서 업로드
   → 필수 열 검사
   → 상태 = "요청서 발송 전" 필터
   → 품목군으로 협력사 매칭 → (구매요청, 협력사) 조합 목록 생성
   → 화면에서 체크/해제, 요청일 확인
   → [제안요청서 만들기] 클릭
   → 조합마다 양식 복사 → 값 채우기 → 메모리에 .docx 저장
   → 결과 목록 + 개별 다운로드 + ZIP 다운로드
```

### 5.2 필드 매핑 규칙
| 요청서 칸 | 값 | 예시 |
|---|---|---|
| 요청번호 | `RFQ-{PR번호에서 'PR-' 뺀 부분}-{협력사}` | `RFQ-2610-001-서진금속` |
| 요청일 | 작성일 `YYYY-MM-DD` | `2026-10-16` |
| 수신 | 협력사 | `서진금속` |
| 수신 담당자 | `{담당자} {직급}` | `오민재 과장` |
| 발신 | 양식 그대로 | |
| 견적 회신 기한 | 작성일 + 3영업일 `YYYY-MM-DD(요일) 17:00` | `2026-10-21(수) 17:00` |
| 품목 / 규격 / 단위 | 구매요청서 그대로 | `SUS304 환봉` |
| 수량 | 천 단위 쉼표 | `800`, `1,000` |
| 희망 납기 | `YYYY-MM-DD` | `2026-10-27` |
| 납품 장소 | 고정 | `천안공장 자재창고` |

### 5.3 영업일 계산
```python
def add_business_days(start, n=3):
    d = start
    while n > 0:
        d += timedelta(days=1)
        if d.weekday() < 5:      # 월~금
            n -= 1
    return d
```
요일은 `["월","화","수","목","금","토","일"][d.weekday()]`로 표기한다. 공휴일은 반영하지 않으며, 화면에서 회신 기한을 직접 고칠 수 있게 한다.

### 5.4 날짜 읽기
엑셀 날짜는 날짜형(datetime), 숫자(엑셀 일련번호), 문자열(`2026-10-27`) 세 경우를 모두 받아 `date`로 바꾼다.

### 5.5 워드 채우기 방식
- 양식 파일을 매번 새로 열어(`Document(BytesIO(template_bytes))`) 건마다 독립된 문서를 만든다.
- 칸에 값을 넣을 때는 셀의 첫 문단에 run을 추가해 **양식의 글꼴·정렬을 유지**한다. 셀 전체를 `cell.text = …`로 덮어쓰지 않는다.
- 표 0의 "발신" 행과 모든 고정 문단은 건드리지 않는다.
- 표 0은 행 순서가 아니라 **왼쪽 칸의 제목 글자**(요청번호, 요청일 …)로 찾아 채운다. 양식 행 순서가 바뀌어도 동작하게 하기 위함이다.

### 5.6 파일명 규칙
`{요청번호 앞부분}_{협력사}_{품목(공백 제거)}.docx`
예: `RFQ-2610-001_서진금속_SUS304환봉.docx`
파일명에 쓸 수 없는 문자(`\ / : * ? " < > |`)는 제거한다.
ZIP 파일명: `제안요청서_{작성일 YYYYMMDD}.zip`

### 5.7 저장 방식
요구사항 "기억 안 함"에 따라 DB나 이력 파일을 두지 않는다. 생성된 파일은 메모리(BytesIO)에만 두고, 사용자가 다운로드한 파일만 PC에 남는다. 앱을 닫으면 사라진다.

## 7. 예외 처리

| 상황 | 처리 |
|---|---|
| 구매요청서에 필수 열이 없음 | 빠진 열 이름을 빨간 오류로 표시하고 중단 |
| 품목군에 맞는 협력사가 없음 | 노란 경고 "PR-xxxx: '○○' 품목군 협력사 없음" 표시, 해당 건은 제외하고 계속 |
| 상태가 "요청서 발송 전"이 아닌 행 | 대상에서 빼고 "n건 제외됨" 안내 |
| 날짜를 읽을 수 없음 | 해당 칸을 빈칸으로 두고 경고 표시 |
| 수량이 숫자가 아님 | 원래 글자를 그대로 넣음 |
| 체크된 건이 0건 | 만들기 버튼 비활성화 |
| 양식 표 구조가 다름 | "양식의 표 구성이 예상과 다릅니다" 오류 표시 |
| 같은 요청번호+협력사 중복 | 한 번만 생성 |

## 9. 모듈 설계 (rfq_core.py)

| 함수 | 입력 | 출력 | 역할 |
|---|---|---|---|
| `load_requests(file)` | 구매요청서 | DataFrame | 읽기, 필수 열 검사, 날짜 변환 |
| `load_suppliers(file)` | 협력사목록 | DataFrame | 읽기, 필수 열 검사 |
| `build_targets(req, sup)` | 두 DataFrame | DataFrame, 경고 목록 | 상태 필터 + 품목군 매칭 |
| `add_business_days(d, n)` | 날짜, 일수 | 날짜 | 영업일 계산 |
| `format_deadline(d)` | 날짜 | 문자열 | `YYYY-MM-DD(요일) 17:00` |
| `make_rfq_docx(template, row, req_date, deadline)` | 양식 바이트, 대상 1건 | 바이트 | 워드 1건 생성 |
| `make_filename(row)` | 대상 1건 | 문자열 | 파일명 생성 |
| `make_zip(files)` | (파일명, 바이트) 목록 | 바이트 | ZIP 생성 |

app.py는 화면만 담당하고, 계산은 모두 rfq_core.py를 호출한다.
