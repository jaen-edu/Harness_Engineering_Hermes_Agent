## 1. 개요

### 1.1 목적
- **메뉴 1 (기존)**: 구매요청서 엑셀 → 협력사별 제안요청서 자동 작성
- **메뉴 2 (신규)**: 구매요청 건별로 들어온 견적서를 업로드하고 **[분석]** 버튼을 누르면, AI가 견적 내용을 읽어 비교표를 만들고 **협상전략**을 제안한다.

### 1.2 왜 AI가 필요한가
받은 견적서 3장의 형식이 모두 다르다.

| 협력사 | 파일 | 형식의 특징 |
|---|---|---|
| 서진금속 | xlsx | 한글 양식, 조건이 "※" 주석 문장으로 흩어져 있음 |
| 경동스틸 | xlsx | 영문 혼용(STS304 Round Bar, D25 x L200), 조건이 표 열에 있음 |
| 대림소재 | pdf | 공문 형식, 조건이 본문 글머리표로 되어 있음 |

칸 위치나 단어가 매번 달라서 고정된 규칙으로는 읽을 수 없다. 그래서 **읽기(추출)와 전략 작성은 AI가 맡고, 금액·날짜 계산은 Python이 맡도록** 역할을 나눈다. AI가 숫자를 틀리게 계산할 위험을 줄이기 위해서다.

### 1.3 범위
| 포함 | 제외 |
|---|---|
| 메뉴 분리(사이드바 메뉴) | 협력사에 메일 자동 발송 |
| 견적서 여러 장 업로드 (xlsx, pdf, png, jpg) | 발주서 작성, ERP 연동 |
| AI 견적 추출 → 사용자 확인·수정 | 과거 견적 이력 저장·추세 분석 |
| Python 비교 계산 (총액, MOQ 반영, 납기 충족 등) | 공휴일 반영 |
| AI 협상전략·협상 메일 초안 | 여러 구매요청 건 동시 분석 |
| 견적비교표 .xlsx, 협상전략 .docx 다운로드 | |

| # | 항목 | 결정 내용 |
|---|---|---|
| 1 | 분석 단위 | **구매요청 1건**(예: PR-2610-001)에 대한 견적서 여러 장 |
| 2 | 지원 파일 | xlsx, pdf(글자 있는 것·스캔본 모두), png, jpg |
| 3 | 실행 | 견적서 업로드 후 **[분석] 버튼 한 번**으로 추출 → 계산 → 전략까지 진행 |
| 4 | 사용자 확인 | AI가 읽은 값을 표로 보여 주고, 고친 뒤 **[다시 분석]** 가능 |
| 5 | 계산 주체 | 총액·실질단가·예상 입고일·납기 충족 여부는 **Python이 계산** (AI 계산 금지) |
| 6 | 협상 우선순위 | 화면에서 선택: `가격 우선` / `납기 우선` / `균형` (기본: 균형) |
| 7 | 결과물 | 화면 표시 + 견적비교표(.xlsx) + 협상전략 보고서(.docx) |
| 8 | 저장 | 하지 않음 (요구사항 "기억 안 함" 유지) |
| 9 | 최종 판단 | AI는 **추천만** 하고, 협력사 선정은 사용자가 한다 |

## 3. 시스템 구성

### 3.1 메뉴 구조
Streamlit의 `st.navigation`으로 사이드바에 메뉴 두 개를 둔다. 메뉴끼리 코드가 섞이지 않도록 화면 파일과 로직 파일을 따로 둔다.

```
[사이드바]
  📝 제안요청서 작성     ← 메뉴 1 (AI 사용 안 함)
  📊 견적 분석·협상전략  ← 메뉴 2 (AI 사용)
  ─────────────
  AI 연결 상태: ● 연결됨 / ○ API 키 없음
```

- API 키가 없어도 메뉴 1은 정상 동작한다. 메뉴 2에서만 키 설정 안내를 보여 준다.
- 메뉴 1에서 올린 구매요청서는 `st.session_state`에 보관해 메뉴 2에서 다시 올리지 않고 쓸 수 있게 한다(앱을 닫으면 사라짐).

### 3.2 기술 스택
| 구분 | 사용 | 용도 | 메뉴 |
|---|---|---|---|
| 언어 | Python 3.10 이상 | | 공통 |
| 화면 | streamlit | 메뉴·업로드·표·다운로드 | 공통 |
| 엑셀 | pandas, openpyxl | 엑셀 읽기, 비교표 xlsx 작성 | 공통 |
| 워드 | python-docx | 제안요청서, 협상전략 보고서 | 공통 |
| PDF 글자 추출 | pdfplumber | 글자가 있는 PDF 읽기 | 2 |
| AI | anthropic (Claude API) | 견적 추출, 협상전략 작성 | 2 |
| 설정 | python-dotenv | API 키·모델명 읽기 | 2 |

- **입력**: 구매요청서.xlsx(필수), 협력사목록.xlsx·양식.docx(내장, 교체 가능)

- **상세 규칙**: v1 문서 5장(필드 매핑·영업일 계산·워드 채우기), 7장(예외 처리), 10장(테스트 T1~T9) 참조

## 5. 메뉴 2 — 견적 분석·협상전략

### 5.1 전체 흐름
```
① 구매요청 선택 (PR-2610-001)
② 견적서 여러 장 업로드
③ [분석] 클릭
   ├─ 3-1. 파일 변환         (Python)  xlsx→표 글자, pdf→글자 또는 원본, 이미지→원본
   ├─ 3-2. 견적 추출         (AI)      견적서 1장당 1회 호출 → 정해진 항목 JSON
   ├─ 3-3. 검증·보완         (Python)  금액 검산, 결제조건 보완, 품목 일치 확인
   ├─ 3-4. 비교 계산         (Python)  MOQ 반영 수량·총액·실질단가·입고일·납기 충족
   └─ 3-5. 협상전략 작성     (AI)      비교표 전체로 1회 호출 → 순위·협상 포인트·메일 초안
④ 결과 확인 → 추출값 수정 시 [다시 분석] (3-3부터 다시 실행, 추출은 반복 안 함)
⑤ 다운로드: 견적비교표.xlsx, 협상전략.docx
```
AI 호출 횟수: **견적서 장수 + 1회** (예: 견적 3장 → 4회). [다시 분석]은 전략 작성 1회만 다시 호출한다.

### 5.2 입력
| 입력 | 필수 | 출처 | 쓰임 |
|---|---|---|---|
| 구매요청서 | ○ | 메뉴 1에서 올린 것 재사용 또는 새로 업로드 | 품목·규격·요청 수량·희망 납기 |
| 구매요청 선택 | ○ | 화면 드롭다운 (상태와 관계없이 전체 건) | 분석 대상 1건 |
| 견적서 파일 | ○ | 업로드, 여러 장 | 추출 대상 |
| 협력사목록 | 내장 | data/ | 결제조건 보완, 담당자·비고 |
| 발주 예정일 | ○ | 화면 (기본: 오늘) | 예상 입고일 계산 |
| 협상 우선순위 | ○ | 화면 (가격/납기/균형, 기본 균형) | 전략 방향 |
| 메모 | | 화면 자유 입력 | 예: "이번 달 예산 빠듯함", "경동스틸 지난달 납기 지연" |

### 5.3 3-1 파일 변환 (quote_reader.py)
| 파일 | 변환 방법 | AI에 보내는 형태 |
|---|---|---|
| xlsx | openpyxl로 모든 시트를 읽고, 빈 칸은 빼고 `셀주소: 값` 형태로 정리 | 글자 |
| pdf (글자 있음) | pdfplumber로 글자 추출 | 글자 |
| pdf (스캔본, 추출 글자 거의 없음) | 원본 파일 그대로 | PDF 문서 블록(base64) |
| png, jpg | 원본 파일 그대로 | 이미지 블록(base64) |

xlsx를 `셀주소: 값`으로 보내는 이유: 서진금속처럼 "※ 운송비: 50,000원 별도" 같은 문장이 병합되지 않은 칸 아무 데나 흩어져 있어도 빠짐없이 전달된다.

### 5.4 3-2 견적 추출 (AI 1단계)
**호출 방식**: Claude API의 도구 호출(tool use) 기능에 아래 항목 형식을 지정하고 그 도구를 반드시 쓰게 해서(`tool_choice` 지정), 항상 같은 모양의 JSON이 오도록 한다.

**함께 보내는 정보**: 구매요청 품목·규격·수량·단위 (같은 품목인지 판단용)

**추출 항목**
| 항목 | 형식 | 예 (서진금속) | 없을 때 |
|---|---|---|---|
| supplier | 글자 | 서진금속 | 필수 |
| quote_no | 글자 | SJ-2610-088 | null |
| quote_date | YYYY-MM-DD | 2026-10-15 | null |
| item_name / spec | 글자 (원문 그대로) | SUS304 환봉 / Ø25 × 200L 절단 | 필수 |
| same_item | true/false + 이유 | true | 필수 |
| quoted_qty | 숫자 | 800 | null |
| unit_price | 숫자 (원, 부가세 별도 기준) | 4800 | 필수 |
| vat_included | true/false/null | false | null |
| moq | 숫자, 제한 없음이면 0 | 0 | null |
| lead_time_days | 숫자 (발주 후 일수) | 7 | null |
| freight_included | true/false/null | false | null |
| freight_amount | 숫자 | 50000 | null |
| payment_terms | 글자 | (견적서에 없음) | null |
| validity_days | 숫자 | 30 | null |
| mill_sheet | true/false/null | true | null |
| other_conditions | 글자 목록 | ["천안공장 도착 기준"] | 빈 목록 |
| evidence | 항목별 원문 근거 | "※ 운송비: 50,000원 별도…" | |

**추출 규칙 (prompts.py에 명시)**
1. 견적서에 **적혀 있는 것만** 옮긴다. 추측해서 채우지 않고, 없으면 null로 둔다.
2. 금액·수량은 쉼표 없는 숫자로 바꾼다. 계산은 하지 않는다.
3. 품목 이름이 달라도 같은 물건이면 same_item=true로 하고 이유를 적는다(예: STS304 = SUS304, D25 x L200 = Ø25 × 200L).
4. 협력사의 제안 문장(예: "1,000개로 조정해 주시면 진행 가능")은 other_conditions에 넣는다.

### 5.5 3-3 검증·보완 (quote_calc.py)
| 검사 | 방법 | 실패 시 |
|---|---|---|
| 금액 검산 | 견적서에 공급가액이 있으면 단가 × 견적수량과 비교 | ⚠ "금액 불일치" 표시 |
| 결제조건 보완 | 견적서에 없으면 협력사목록 값 사용 | 출처를 "협력사목록"으로 표시 |
| 협력사 확인 | 이름 정리(㈜·주식회사·공백 제거) 후 협력사목록과 대조 | ⚠ "목록에 없는 협력사" |
| 품목 확인 | same_item=false | ⚠ "요청 품목과 다름", 비교에서 제외 여부를 사용자가 선택 |
| 필수값 누락 | 단가가 null | 비교에서 제외하고 "직접 입력 필요" 표시 |
| 중복 | 같은 협력사 견적 2장 | 견적일이 늦은 것 사용, 안내 표시 |

### 5.6 3-4 비교 계산 (quote_calc.py, AI 미사용)
| 계산값 | 식 |
|---|---|
| 실구매수량 | max(요청수량, MOQ) |
| 잉여 수량 | 실구매수량 − 요청수량 |
| 운송비 | 포함이면 0, 별도면 freight_amount, 미기재면 null(⚠ 확인 필요) |
| 총액 | 단가 × 실구매수량 + 운송비 |
| 실질단가 | 총액 ÷ 요청수량 (요청 수량 1개당 실제로 드는 돈) |
| 예상 입고일 | 발주 예정일 + 리드타임(달력일) |
| 납기 충족 | 예상 입고일 ≤ 희망 납기 → "충족" / 아니면 "n일 지연" |
| 견적 만료일 | 견적일 + 유효기간 |
| 만료 임박 | 만료일까지 7일 이하이면 ⚠ |
| 순위(참고) | 실질단가 오름차순, 납기 미충족은 뒤로 |

### 5.7 3-5 협상전략 작성 (AI 2단계)
**보내는 정보**: 구매요청 1건, 3-4 비교표(JSON), 협력사 정보(결제조건·거래 시작·비고), 협상 우선순위, 사용자 메모

**출력 항목 (도구 호출로 형식 고정)**
| 항목 | 내용 |
|---|---|
| summary | 결론 3문장 이내 |
| ranking | 협력사별 추천 순위와 이유 |
| supplier_points | 협력사별 강점, 약점, 요청할 사항(목록), 목표 조건(목표 단가·납기 등), 근거 |
| scenario | 1차 협상안 → 결렬 시 대안 → 최종 선택지 |
| risks | 확인이 필요한 것 (미기재 항목, 만료 임박, 납기 지연 등) |
| email_drafts | 협력사별 협상 요청 메일 초안 (제목, 본문) |

**전략 작성 규칙**
1. 금액·날짜는 **비교표에 있는 숫자만** 인용한다. 새로 계산하지 않는다.
2. 목표 단가를 제안할 때는 근거(다른 협력사 견적, 운송비 차이 등)를 함께 적는다.
3. **메일 초안에는 다른 협력사의 회사명과 견적 금액을 쓰지 않는다.** "타사 견적 대비 높은 수준" 정도로만 표현한다(구매 윤리·비밀유지).
4. 협상 우선순위에 따라 가중치를 달리한다.
5. 정보가 부족한 부분은 단정하지 않고 risks에 "확인 필요"로 남긴다.

| 일부 견적 추출 실패 | 실패한 파일만 표시하고 나머지로 계속 진행, 수동 입력 행 추가 가능 |

### 5.11 보안·운영
- 견적서 내용은 분석을 위해 **Anthropic API로 전송**된다. 협력사 견적은 영업 비밀일 수 있으므로 사내 정보보안 규정상 외부 AI 사용이 허용되는지 먼저 확인한다.
- API 키는 `.env`에만 두고, 폴더를 다른 사람에게 줄 때는 `.env`를 빼고 준다.
- API 사용료는 호출 횟수와 분량에 따라 나온다. 사용량은 Anthropic Console에서 확인한다.
- 앱은 견적 원본·분석 결과를 저장하지 않는다. 사용자가 내려받은 파일만 남는다.
