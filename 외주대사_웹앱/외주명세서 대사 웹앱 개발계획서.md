# 외주명세서 대사 웹앱 개발계획서

Oct 16, 2026 · @kangyu

## 1. 개요

업체별 외주 거래명세서(PDF 스캔본)와 ERP 외주입고이력(엑셀)을 자동으로 대사해, 틀린 곳을 **어느 업체·어느 파일·몇 페이지·몇 번째 행·어느 항목**까지 짚어주는 Streamlit 웹앱을 만든다.

- **배경**: 매월 7개 업체, 약 130건의 명세서 행을 ERP와 눈으로 맞추고 있어 마감 시간이 길고 누락 위험이 있다.
- **사용자**: 구매팀 외주마감 담당자 1인 (사내 PC에서 단독 실행).
- **범위**: 공급가액 기준 대사. 세액은 참고용으로만 표시한다(9월 샘플에서 업체 반올림과 ERP 절사 방식 차이로 1원 차이가 13건 확인됨).
- **범위 밖**: ERP 자동 반영·수정, 세금계산서 발행, 업체 앞 메일 발송.
- **기대효과**: 월 대사 작업을 "전 행 수기 확인"에서 "불일치 행만 확인"으로 바꾼다. 9월 샘플 기준 확인 대상이 135행에서 약 12건으로 줄어든다.
- **판정 근거**: 요구사항 초안의 기준(엑셀 읽기·AI 사용·내보내기 버튼)에 모두 해당하므로 Python + Streamlit + 실행.bat 구성으로 한다.

## 2. 입력 데이터 분석

명세서 PDF 7개는 모두 **텍스트가 없는 스캔 이미지**라서 일반 PDF 텍스트 추출로는 읽을 수 없다. 이미지 판독(AI 비전 또는 OCR)이 필수다. 양식도 업체마다 4가지로 달라 업체별 판독 규칙이 필요하다.

**ERP 외주입고이력** (시트 `입고이력`, 135행 × 15열): 입고일자, 입고번호, 발주번호, 업체코드, 업체명, 품번, 품명, 입고수량, 단위, 단가, 공급가액, 부가세, 합계금액, 입고창고, 입고담당자. 공급가액 = 수량 × 단가는 전 행 일치한다.

| 업체 | 파일 | 페이지 | 행 수 | 양식 특징 | 판독 시 주의점 |
| --- | --- | --- | --- | --- | --- |
| (주)대성정밀 | 대성정밀\_거래명세서 | 2 | 20 | 월합계 표준형, 일자 YYYY-MM-DD | — |
| 동아사출산업 | 동아사출\_거래명세서 | 2 | 22 | 월합계 표준형, 일자 MM/DD | 연도 없음 → 거래기간에서 보충 |
| (주)성원금속 | 성원금속\_거래명세표 | 2 | 14 | 가로형, 월·일 분리 열 | **발주번호 없음**, 품번 열 이름이 "도면번호" |
| 세진열처리 | 세진열처리\_거래명세서 | 2 | 20 | 월합계 표준형, 일자 YYYY.MM.DD | — |
| (주)우림도장 | 우림도장\_거래명세서 | 2 | 21 | 월합계 표준형 | **손글씨 정정**(1행 수량 62→60, 비고 "정정") |
| 한성유압정공(주) | 한성유압\_거래명세서 | 9 | 16 | **납품 건별 1장**, 명세서 번호 HS-2609-xxx | **△ 반품(차감) 행**, 수기 서명 |

모든 명세서는 인쇄된 합계와 행 합계가 일치했다. 이 "명세서 자체 검산"을 판독 정확도 검증 장치로 쓴다(5장).

## 4. 기능 요구사항

필수 기능은 초안의 출력 3가지(업체별 요약, 불일치 리포트, 클릭 시 PDF 페이지 표시)이고, 판독 오류를 사람이 잡을 수 있게 하는 확인·수정 단계와 엑셀 내보내기를 추가했다.

| ID | 기능 | 내용 | 우선순위 |
| --- | --- | --- | --- |
| F1 | 파일 업로드 | ERP 엑셀 1개 + 명세서 PDF 여러 개를 한 번에 올린다. 파일명·명세서 상호로 업체를 자동 인식하고, 못 찾으면 드롭다운으로 지정한다. | 필수 |
| F2 | 명세서 판독 | 페이지 이미지를 AI로 읽어 행 단위 표(업체, 파일, 페이지, 행번호, 일자, 발주번호, 품번, 수량, 단가, 공급가액, 반품 여부, 비고)로 만든다. | 필수 |
| F3 | 판독 검산 | 행별 수량×단가=공급가액, 명세서 인쇄 합계=행 합계를 자동 확인해 판독 의심 행을 노란색으로 표시한다. | 필수 |
| F4 | 판독 결과 확인·수정 | 대사 전에 판독 표를 화면에서 직접 고칠 수 있다(손글씨 정정, 흐린 숫자 대비). | 필수 |
| F5 | 대사 실행 | 5장의 규칙으로 업체·일자·품번 단위 매칭 후 불일치 유형을 판정한다. | 필수 |
| F6 | 업체별 요약 | 업체별 명세서 합계, ERP 합계, 차이, 불일치 건수, 판정(일치/불일치)을 한 표로 보여준다. | 필수 |
| F7 | 불일치 리포트 | 불일치 행마다 업체, 파일명, 페이지, 행번호, 틀린 항목, 명세서 값, ERP 값, 차액, ERP 입고번호를 보여준다. 업체·유형으로 거를 수 있다. | 필수 |
| F8 | PDF 페이지 보기 | 리포트 행을 선택하면 옆 패널에 해당 PDF 페이지 이미지를 띄우고 문제 행 위치를 표시한다. | 필수 |
| F9 | 엑셀 내보내기 | 요약·불일치 리포트·판독 원본 3개 시트를 담은 엑셀을 내려받는다. | 필수 |
| F10 | 업체 회신용 문구 | 불일치 건을 업체별로 묶어 확인 요청 문구 초안을 만든다. | 선택(2차) |

초안 6번(기억 안 함)에 따라 판독 결과와 리포트는 서버나 PC에 저장하지 않는다. 앱을 닫으면 사라지며, 남기고 싶으면 F9로 내려받는다.

## 5. 대사 로직 설계

기본 매칭 키는 **업체 + 일자 + 품번**이고, 1차에서 짝을 못 찾은 행만 느슨한 키로 다시 맞춰 "일자 어긋남", "품번 어긋남"을 찾아낸다. 발주번호는 성원금속 명세서에 없어서 키에서 빼고 참고값으로만 비교한다.

1. **정규화**: 업체명은 업체 마스터(업체코드 ↔ 명세서 상호)로 통일한다. 일자는 YYYY-MM-DD로 바꾸고, 연도가 없으면 명세서 거래기간 연도를 붙인다. 품번은 공백·하이픈 표기를 통일한다. 반품(△) 행은 수량·금액을 음수로 바꾼다.
2. **집계**: 같은 업체·일자·품번에 여러 행이 있으면 양쪽 모두 합산한 뒤 비교한다(분할 입고 대응). 단, ERP에서 같은 날 같은 수량 행이 2개 이상이면 "중복 의심" 표시를 붙인다.
3. **1차 매칭**(업체+일자+품번): 수량, 단가, 공급가액을 순서대로 비교해 처음 다른 항목을 유형으로 기록한다.
4. **2차 매칭**(남은 행끼리): 업체+품번+공급가액이 같고 일자가 7일 이내면 "일자 불일치", 업체+일자+공급가액(또는 수량)이 같고 품번만 다르면 "품번 불일치"로 짝짓는다.
5. **잔여 판정**: 그래도 남은 명세서 행은 "ERP 미입고", ERP 행은 "명세서 누락"이다. 명세서 쪽 음수 행이 남으면 "반품 미반영"으로 바꿔 부른다.
6. **묶음 표시**: 같은 발주번호·같은 단가 차이가 반복되면 리포트에서 한 묶음으로 접어 보여준다(예: 대성정밀 PO2609-0133 단가 4건).
7. **업체 합계 판정**: 업체별 공급가액 합계 차이가 0원이고 행 불일치도 0건일 때만 "일치"로 본다.

| 유형 | 판정 조건 | 담당자 조치 예시 |
| --- | --- | --- |
| 수량 불일치 | 키 일치, 수량 다름 | 입고 전표 수량 확인 |
| 단가 불일치 | 키·수량 일치, 단가 다름 | 단가 계약·발주 단가 확인 |
| 금액 불일치 | 수량·단가 일치, 공급가액만 다름 | 업체 계산 오류 확인 |
| 일자 불일치 | 2차 매칭, 금액 같고 일자만 다름 | 마감월 경계면 귀속월 확인 |
| 품번 불일치 | 2차 매칭, 품번만 다름 | ERP 품번 입력 오류 확인 |
| ERP 미입고 | 명세서에만 있음 | 입고 누락 처리 |
| 명세서 누락 | ERP에만 있음 | 업체에 명세서 추가 요청 |
| ERP 중복 의심 | ERP 동일 행 2개 이상 | 중복 전표 취소 검토 |
| 반품 미반영 | 명세서 △행, ERP 없음 | ERP 반품 전표 등록 |
| 정정 표기 | 판독 시 손글씨·취소선 감지 | 정정 값 육안 확인(금액 영향 없으면 참고) |

허용 오차는 공급가액 0원으로 둔다. 세액은 비교하지 않고 표시만 한다.

## 6. 시스템 구성

Python + Streamlit 단일 앱을 사내 PC에서 `실행.bat`으로 띄우고, 스캔 명세서 판독만 Claude API(이미지 인식)에 맡긴다. 나머지 매칭·검산·리포트는 모두 PC 안에서 pandas로 처리한다.

| 구분 | 선택 | 이유 |
| --- | --- | --- |
| 화면 | Streamlit | 표 편집(`st.data_editor`), 행 선택, 파일 업로드·다운로드가 기본 제공 |
| 엑셀 읽기·쓰기 | pandas + openpyxl | ERP 엑셀 읽기, 결과 엑셀 서식 지정 |
| PDF → 이미지 | PyMuPDF | 윈도우에서 별도 프로그램 설치 없이 페이지 이미지 생성 |
| 명세서 판독 | Claude API (이미지 입력, JSON 출력) | 업체별 양식 4종·손글씨 정정·△반품 표기를 규칙 없이 읽을 수 있음 |
| 판독 대안 | PaddleOCR(로컬) | 외부 전송이 불가할 때 예비안. 표 구조·손글씨 정확도가 낮아 F4 수정 부담이 커짐 |
| 설정 | `.env`(API 키), `vendors.yaml`(업체 마스터) | 업체 추가 시 코드 수정 없이 설정만 변경 |

**판독 방식**: 페이지 1장씩 이미지로 보내고, 행 목록과 인쇄 합계를 정해진 JSON 형식으로 받는다. 각 행의 세로 위치(페이지 높이 대비 %)도 함께 받아 F8에서 해당 행에 강조 띠를 그린다. 위치를 못 받으면 페이지만 띄우고 행번호를 표시한다. 9월 기준 23페이지 × 1회 호출이며, 실행 중에만 메모리에 두고 같은 파일 재대사 시 다시 부르지 않는다.

**폴더 구조**

```
외주대사앱/
```

**화면 구성**

- **왼쪽 사이드바**: ERP 엑셀 업로드, 명세서 PDF 여러 개 업로드, 업체 자동 인식 결과, \[판독 시작\] · \[대사 실행\] 버튼, 진행률.
- **탭 1 · 업체별 요약**: 4장 F6 표와 상단 지표(전체 차액, 불일치 업체 수, 불일치 건수), \[엑셀 내려받기\] 버튼.
- **탭 2 · 불일치 리포트**: 왼쪽에 불일치 표(업체·유형 필터), 오른쪽에 선택한 행의 PDF 페이지 이미지와 강조 띠. 명세서 값과 ERP 값을 나란히 보여준다.
- **탭 3 · 판독 결과 확인**: 업체별 판독 표를 편집 가능하게 띄우고, 검산 실패 행은 노란색. 수정 후 \[다시 대사\].

## 7. 개발 일정과 단계

4주, 5단계로 나눠 **10월분 마감(11월 초)에 수기 대사와 병행 사용**, 11월분부터 단독 사용을 목표로 한다. 각 단계는 9월 샘플로 완료 여부를 확인한다.

| 단계 | 기간 | 작업 | 완료 기준 |
| --- | --- | --- | --- |
| 0. 준비 | 1주차 초 | 실행.bat·폴더 구성, API 키 발급, 업체 마스터(vendors.yaml) 작성, 9월 정답지 정리 | 실행.bat로 빈 화면이 뜸 |
| 1. 판독 | 1\~2주차 | PDF→이미지, AI 판독 프롬프트, 업체 양식별 보정(연도 보충, △반품, 성원금속 열 구성), 검산(F3) | 9월 7개 파일 134행 판독, 명세서 합계 7개 모두 일치 |
| 2. 대사 | 2주차 | ERP 정규화, 1·2차 매칭, 유형 판정 | 3장의 행 단위 불일치 11건을 모두 같은 유형으로 검출 |
| 3. 화면·리포트 | 3주차 | 요약·리포트·판독 확인 탭, PDF 페이지 보기와 강조 띠, 엑셀 내보내기 | 리포트 행 클릭 시 해당 페이지가 3초 안에 표시 |
| 4. 병행 운영 | 4주차\~10월분 마감 | 10월분으로 수기 대사와 결과 비교, 오판 사례 반영 | 수기 결과와 차이 0건 |
| 5. 확장(선택) | 이후 | F10 업체 회신 문구, 업체 추가 | — |

## 8. 테스트 계획, 리스크, 결정 필요 사항

가장 큰 리스크는 판독 오류이며, 명세서 자체 검산과 판독 확인 화면(F4) 두 겹으로 막는다. 사내 보안 승인 여부가 판독 방식을 결정하므로 착수 전에 확인이 필요하다.

**테스트 계획**

| 구분 | 방법 | 합격 기준 |
| --- | --- | --- |
| 판독 정확도 | 9월 134행을 정답지와 칸 단위 비교 | 금액·수량·품번 오류 0건, 일자 오류 0건 |
| 검산 | 판독 값 하나를 일부러 바꿔 넣기 | 해당 행·업체 합계가 노란색으로 표시 |
| 대사 규칙 | 3장 불일치 11건 + 일치 업체(한울도금) | 유형·위치(파일·페이지·행) 모두 일치, 한울도금 "일치" |
| 경계 사례 | 월말 입고 다음 달 귀속, 같은 날 분할 입고, 업체명 표기 변형 | 오판 없이 "일자 불일치" 또는 합산 매칭 |
| 화면 | 리포트 행 클릭 → PDF 표시, 엑셀 내려받기 | 표시·다운로드 정상, 엑셀 3개 시트 |

**리스크와 대응**

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 스캔 품질 저하·손글씨로 숫자 오판독 | 틀린 불일치 보고 또는 불일치 놓침 | 수량×단가 검산, 명세서 합계 검산, F4 수정 후 재대사 |
| 업체가 양식을 바꿈 | 판독 실패 | AI 판독은 양식 규칙에 의존하지 않음. 실패 시 검산에서 바로 드러남 |
| 명세서 이미지의 외부(API) 전송 | 보안 정책 위반 가능 | 착수 전 보안 담당 확인. 불가 시 로컬 OCR 예비안으로 전환 |
