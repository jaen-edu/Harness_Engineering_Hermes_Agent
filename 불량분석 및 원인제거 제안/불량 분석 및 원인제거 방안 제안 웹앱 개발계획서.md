# 불량 분석 및 원인제거 방안 제안 웹앱 개발계획서

Oct 16, 2026 · @kangyu

## 1. 개요

주간 불량 집계·분석·원인 추정을 파일 업로드 한 번으로 끝내는 Streamlit 웹앱을 5일(2026-10-19 \~ 10-23)에 걸쳐 만든다. 사용자는 한빛전자 품질팀 대리 1명이며, 결과는 매주 월요일 품질회의 보고 자료로 쓴다.

| 항목 | 내용 |
| --- | --- |
| 현재 문제 | 생산수량·불량기록·현장 메모·지난주 리포트를 손으로 취합하느라 매주 분석 시간이 길다 |
| 목표 | 업로드 → 집계·분석 대시보드 → TOP3 불량 원인 제거방안 AI 제안 → 주간 리포트 내보내기 |
| 사용자 | 혼자 사용, 로그인 없음 |
| 저장 | 기억하지 않음. 매번 파일을 올려서 계산하고, 결과는 내보내기 파일로만 남긴다 |
| 형태 | Python + Streamlit, `실행.bat` 더블클릭 실행, AI API 키는 `.env` 파일 |

기대효과는 주간 분석 작업을 반나절에서 30분 이내로 줄이고, 불량을 건수가 아닌 수량·불량률 기준으로 판단하게 만드는 것이다. 지난주 W41 리포트는 도장불량을 "건수가 적다"며 관찰로 두었지만, 수량으로 보면 W38 21개에서 W41 107개로 이미 5배 늘어 있었다.

## 2. 입력 데이터 분석

입력은 4종 9개 파일이며, 생산수량이 라인 단위로만 있어 불량률은 "주차 × 라인"까지만 계산할 수 있다. 품번별 분석은 불량률이 아니라 불량 수량과 점유율로 보여준다.

| 파일 | 구조 | 앱에서의 쓰임 | 주의점 |
| --- | --- | --- | --- |
| 생산수량\_주별.xlsx | 시트 `생산수량`, 20행 × 6열 (주차·시작일·종료일·근무일수·라인·생산수량), W38\~W42 × 4개 라인 | 불량률 분모, 근무일수 표시 | 라인별 합계만 있음. W39 근무일 3일, W41 4일 |
| 불량기록\_W38\~W42.xlsx (5개) | 시트 `불량기록`, 10열 (발생일·라인·품번·품명·출하처·불량유형·불량수량·발견 공정·조치·기록자), 합계 223행 | 집계·분석의 원천 | 결측 없음. `조치`에 비표준 값 1종("10/13 생산분 전수 선별", 9건) |
| 지난주\_불량분석리포트\_W41.docx | 제목, 개요, 유형별 건수 표, 라인별 불량률 표, 원인 추정·다음 주 조치, 특이사항 | 지난주 조치 이행 확인용 AI 입력, 내보내기 리포트 양식 | 건수 기준으로 순위를 매김 |
| 현장 메모 (md 또는 텍스트 붙여넣기) | 설비 변경, 자재 로트 변경, 고객 클레임, 기타 | 원인 추정의 근거 (AI 입력) | 정형 데이터 아님. 날짜·라인·품번을 AI가 연결해야 함 |

불량기록 기준 주차는 발생일의 ISO 주차로 계산하며, 생산수량의 주차 표기(W38 = 2026-09-14 시작)와 일치함을 확인했다. 파일명의 주차는 검증용으로만 쓰고, 발생일과 어긋나면 경고한다.

샘플 데이터로 계산한 W42 결과는 앱 검증의 기준값으로 쓴다.

| 지표 (W42) | 값 | 비고 |
| --- | --- | --- |
| 전체 불량률 | 3.96% (552개 / 13,950개) | W41 3.98%와 비슷 |
| 라인별 불량률 | 1라인 4.70%, 2라인 5.92%, 3라인 1.16%, 4라인 4.01% | 1라인은 W38 0.88%에서 5주 연속 상승 |
| 유형별 수량 TOP3 | 버(burr) 198개, 도장불량 193개, 치수불량 90개 | 도장불량 +86개, 치수불량 +41개 (전주 대비) |
| 집중 구간 | 1라인 PN-1011 도장불량 146개, 2라인 PN-1003 치수불량 64개 (전량 10/13) | 현장 메모의 도료 로트 변경(9/21), MCT-02 척 교체(10/13)와 시점이 맞음 |

## 3. 기능 요구사항

필수 기능은 12개이며, 1차 개발 범위는 F-01 \~ F-12 전부다.

| ID | 기능 | 상세 | 구분 |
| --- | --- | --- | --- |
| F-01 | 파일 업로드 | 생산수량 1개, 불량기록 여러 개(xlsx·csv), 지난주 리포트(docx, 선택), 현장 메모(md·txt 업로드 또는 텍스트 붙여넣기) | 입력 |
| F-02 | 입력 검증 | 필수 열 존재, 불량수량 숫자·양수, 라인명·주차가 생산수량과 매칭되는지 확인. 문제 행은 표로 보여주고 제외 여부 선택 | 입력 |
| F-03 | 분석 주차 선택 | 기본값은 데이터 중 가장 최근 주차(W42), 비교 범위는 최근 5주 | 입력 |
| F-04 | KPI 카드 | 이번 주 생산수량, 불량 수량, 불량 건수, 불량률, 전주 대비 증감(%p) | 집계 |
| F-05 | 주차 × 라인 불량률 | 표 + 라인별 추이 꺾은선 그래프, 근무일수 함께 표시 | 집계 |
| F-06 | 유형별 추이 | 불량유형 × 5주 수량 표와 그래프, 건수도 함께 표시 | 집계 |
| F-07 | 파레토 | 이번 주 불량유형·품번별 수량 파레토 (누적 80% 선 표시) | 분석 |
| F-08 | 교차 분석 | 라인 × 품번 × 유형 상위 10개, 출하처별, 발견 공정별(출하검사 비중) 분포 | 분석 |
| F-09 | 변화점 감지 | 전주 대비 급증 유형, 하루 집중 발생, 출하검사 발견 비중 증가를 자동 표시 | 분석 |
| F-10 | TOP3 선정 | 이번 주 불량 수량 기준 상위 3개 유형. 사용자가 순위를 바꿀 수 있음 | AI |
| F-11 | AI 원인·제거방안 제안 | TOP3 각각에 추정 원인, 근거, 확인 방법, 단기·근본 대책, 담당 부서, 클레임 연계 제시 | AI |
| F-12 | 내보내기 | 주간 리포트 Word(W41 리포트와 같은 목차), 집계표 Excel, AI 제안 Markdown | 출력 |

제외 범위는 로그인, 데이터 누적 저장(DB), 다중 사용자, ERP 자동 연동이다. 이력은 사용자가 매주 파일을 올리는 방식으로만 관리한다.

## 4. 처리 로직

모든 숫자는 pandas로 먼저 계산하고, AI는 계산된 결과만 받아 원인을 추정한다. AI가 숫자를 직접 세지 않게 해서 집계 오류를 막는다.

1. 불러오기: 불량기록 파일을 하나로 합치고 `주차 = 발생일의 ISO 주차(W##)` 열을 만든다.
2. 정리: 열 이름 공백 제거, 라인명 표기 통일("1 라인" → "1라인"), 조치 값이 표준 목록에 없으면 "기타"로 묶고 원문은 보존한다.
3. 집계: 주차 × 라인 기준으로 불량 수량을 합치고 생산수량과 결합한다.
4. 분석: 파레토, 교차 분석, 변화점 규칙을 적용한다.
5. AI 입력 만들기: 집계 결과 요약 + 변화점 + 현장 메모 + 지난주 리포트 본문을 하나의 프롬프트로 묶는다.

불량률 계산식은 다음과 같다. 품번별 생산수량이 없으므로 품번 단위 불량률은 계산하지 않는다.

```latex
\text{불량률}_{w,l} = \frac{\sum \text{불량수량}_{w,l}}{\text{생산수량}_{w,l}} \times 100\ (\%)
```

변화점 감지 규칙은 아래 4개로 시작하고, 기준값은 `config.py`에서 바꿀 수 있게 한다.

| 규칙 | 조건 (기본값) | W42 샘플에서 걸리는 항목 |
| --- | --- | --- |
| 유형 급증 | 전주 대비 수량 +50% 이상이면서 +30개 이상 | 도장불량 107 → 193, 치수불량 49 → 90 |
| 연속 상승 | 라인 불량률 3주 이상 연속 상승 | 1라인 0.88% → 4.70% (5주 연속) |
| 하루 집중 | 한 품번·유형의 주간 수량 중 70% 이상이 하루에 발생 | 2라인 PN-1003 치수불량 64개 전량 10/13 |
| 유출 위험 | 출하검사 발견 비중이 해당 유형의 30% 이상 | 도장불량 112/193개(58%, 클레임 2건과 연결), 이물·오염 9/9개 |

건수와 수량을 함께 보여주되 순위와 TOP3는 수량 기준으로 정한다. W41 리포트가 건수 기준이어서 도장불량 증가를 놓친 점을 반영한 결정이다.

## 5. AI 제안 설계

AI는 Anthropic Claude API를 한 번 호출해 TOP3 유형 각각의 원인과 제거방안을 JSON으로 받고, 앱이 이를 카드로 보여준다. 버튼을 눌렀을 때만 호출해 비용과 대기 시간을 통제한다.

AI에 보내는 입력은 다음 5가지다.

1. 분석 주차와 TOP3 유형, 각 유형의 5주 수량 추이와 전주 대비 증감
2. TOP3 유형별 라인 × 품번 × 출하처 × 발견 공정 상위 내역, 일자별 수량
3. 변화점 감지 결과 (4장의 규칙에 걸린 항목)
4. 현장 메모 원문
5. 지난주 리포트의 "원인 추정 · 다음 주 조치" 본문 (조치 이행 여부를 묻기 위함)

시스템 프롬프트의 핵심 지시는 아래와 같다.

- 너는 제조 품질 엔지니어다. 4M(사람·설비·자재·방법) 관점으로 원인을 추정한다.
- 숫자는 제공된 집계값만 인용하고 새로 계산하지 않는다.
- 현장 메모의 날짜·라인·품번과 불량 발생 시점이 맞는 경우만 "근거 있음"으로 표시하고, 아니면 "추정"으로 표시한다.
- 지난주 조치가 이번 주 결과에 반영됐는지 한 줄로 평가한다.
- JSON 외 다른 글은 쓰지 않는다.

출력 JSON 형식은 다음과 같다.

| 필드 | 내용 | W42 예상 예시 (도장불량) |
| --- | --- | --- |
| rank, defect\_type | 순위, 불량유형 | 2, 도장불량 |
| phenomenon | 숫자로 쓴 현상 | 1라인 193개, 전주 대비 +86개, 출하검사 발견 58% |
| suspected\_causes | 원인 후보 목록 (4M 구분, 근거, 신뢰도 상·중·하) | 자재: 도료 LOT 2609-B 사용(9/21\~) 이후 증가, 작업자 "도막이 얇다" 진술 / 신뢰도 상 |
| verification | 원인 확인 방법 | 구 로트와 신 로트 점도·도막 두께 비교 측정 |
| short\_term | 단기 조치 (1주 이내) | 출하 전 도막 두께 전수 측정, 10/7·10/8 출하분 추적 |
| permanent | 근본 대책 | 공급사 로트 성적서 수입검사 항목에 점도 추가 |
| owner | 담당 부서 | 구매팀(도료), 생산 1라인 |
| claim\_link | 관련 클레임 | CL-2610-03, CL-2610-04 (회신 기한 10/22) |
| last\_week\_check | 지난주 조치 평가 | W41에서 관찰로 두었으나 수량 +80% 증가 |

JSON 파싱에 실패하면 한 번 재시도하고, 그래도 실패하면 원문 응답을 그대로 보여준다. 사용자는 카드마다 내용을 고칠 수 있고, 고친 내용이 내보내기에 들어간다.

## 6. 화면 구성

화면은 왼쪽 사이드바(입력)와 본문 탭 4개로 나눈다. 탭 순서는 실제 작업 순서인 집계 → 분석 → AI 제안 → 내보내기를 따른다.

| 영역 | 구성 요소 | 비고 |
| --- | --- | --- |
| 사이드바 | 파일 업로드 4칸, 현장 메모 텍스트 상자, 분석 주차 선택, 비교 주 수(기본 5), API 키 상태 표시 | 키가 없으면 "`.env`에 ANTHROPIC\_API\_KEY를 넣으세요" 안내 |
| 탭 1 집계 대시보드 | KPI 카드 5개, 주차 × 라인 불량률 표와 추이 그래프, 유형별 5주 추이 | 전주 대비 증감은 색(상승 빨강, 하락 파랑)과 화살표로 함께 표시 |
| 탭 2 분석 대시보드 | 유형 파레토, 품번 파레토, 라인 × 품번 × 유형 상위 10, 출하처·발견 공정 분포, 변화점 알림 목록 | 변화점 항목을 누르면 해당 원본 행 표시 |
| 탭 3 AI 제안 | TOP3 확인·순서 변경, "AI 제안 받기" 버튼, 원인별 카드 3장 (편집 가능) | 근거 있음·추정 구분 배지 |
| 탭 4 내보내기 | 리포트 미리보기, Word·Excel·Markdown 다운로드 버튼 | 파일명 `불량분석리포트_W42.docx` 형식 |

그래프는 Plotly를 쓴다. 마우스를 올리면 값이 보이고, 리포트용 이미지는 같은 데이터로 matplotlib에서 다시 그려 Word에 넣는다.

## 7. 기술 스택과 폴더 구조

엑셀을 읽고, AI를 쓰고, 내보내기 버튼이 있으므로 판정 기준에 따라 Python + Streamlit으로 만든다. API 키는 코드에 넣지 않고 `.env` 파일에서만 읽는다.

| 구분 | 선택 | 용도 |
| --- | --- | --- |
| 언어 | Python 3.11 이상 |  |
| 화면 | streamlit | 웹 화면, 파일 업로드, 다운로드 버튼 |
| 데이터 | pandas, openpyxl | 엑셀 읽기·집계, Excel 내보내기 |
| 그래프 | plotly, matplotlib | 화면 그래프 / Word 삽입용 이미지 |
| 문서 | python-docx | 지난주 리포트 읽기, 주간 리포트 Word 생성 |
| AI | anthropic | Claude API 호출 |
| 설정 | python-dotenv | `.env`에서 API 키·모델명 읽기 |

```
불량분석앱/
├─ 실행.bat              # 가상환경 생성 → 패키지 설치 → streamlit 실행
├─ app.py                # 화면 (사이드바 + 탭 4개)
├─ config.py             # 변화점 기준값, 표준 불량유형·조치 목록
├─ core/
│  ├─ loader.py          # 파일 읽기, 열 정리, 주차 계산, 입력 검증
│  ├─ aggregate.py       # KPI, 주차×라인 불량률, 유형별 추이
│  ├─ analyze.py         # 파레토, 교차 분석, 변화점 감지
│  ├─ ai_advisor.py      # 프롬프트 생성, Claude 호출, JSON 파싱
│  └─ report.py          # Word·Excel·Markdown 내보내기
├─ prompts/
│  └─ system_prompt.md   # AI 지시문 (코드 수정 없이 고칠 수 있게 분리)
├─ sample_data/          # 이번에 받은 W38~W42 파일 (검증용)
├─ tests/                # 기준값 검증 테스트
├─ requirements.txt
├─ .env.example          # 키 자리만 있는 견본 (배포용)
├─ .env                  # 실제 키 (직접 생성, 공유 금지)
└─ .gitignore            # .env 제외
```

`.env` 파일 내용은 아래 2줄이다. 모델명을 코드가 아닌 `.env`에 두어 모델을 바꿀 때 코드를 고치지 않게 한다.

```
ANTHROPIC_API_KEY=sk-ant-여기에_키_입력
ANTHROPIC_MODEL=claude-sonnet-5-5
```

API 키 처리 원칙은 다음과 같다.

- 앱 시작 시 `load_dotenv()`로 읽고, 키가 없으면 AI 탭만 비활성화하고 집계·분석 탭은 그대로 쓴다.
- 화면·로그·내보내기 파일 어디에도 키를 표시하지 않는다. 사이드바에는 "연결됨 / 키 없음"만 보여준다.
- `실행.bat`은 `.env`가 없으면 `.env.example`을 복사해 만들고 메모장으로 열어 키 입력을 안내한다.
- `.gitignore`에 `.env`를 넣고, 다른 사람에게 폴더를 줄 때는 `.env`를 빼고 준다.

## 10. 리스크와 대응

가장 큰 리스크는 AI가 근거 없는 원인을 그럴듯하게 쓰는 것이며, 근거 표시와 사람의 편집으로 막는다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| AI가 근거 없는 원인 제시 | 잘못된 대책 실행 | 숫자는 앱 계산값만 사용, "근거 있음 / 추정" 배지, 카드 편집 후 내보내기 |
| 품번별 생산수량 없음 | 품번 단위 불량률 계산 불가 | 수량·점유율로 표시. 생산 실적에 품번 열이 생기면 자동으로 품번 불량률 계산 |
| 엑셀 양식 변경 | 불러오기 실패 | 열 이름 별칭 목록을 `config.py`에 두고, 필수 열이 없으면 어떤 열이 없는지 표시 |
| 근무일수 차이 (W39 3일, W41 4일) | 수량만 보면 추이 왜곡 | 추이는 불량률 기준으로 그리고, 근무일수를 함께 표시 |
| 비표준 조치 값 | 조치별 집계 분산 | "기타"로 묶고 원문 보존, 화면에 비표준 값 목록 표시 |
| API 키 노출 | 비용 도용 | `.env`에만 저장, 화면·로그 비표시, `.gitignore` 등록 |
| API 오류·지연 | AI 탭 사용 불가 | 30초 제한 시간, 1회 재시도, 실패해도 집계·분석·내보내기는 동작 |
