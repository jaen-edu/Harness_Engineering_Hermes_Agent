# 한빛정밀 생산관리팀 에이전트

이 폴더는 한빛정밀 생산관리팀의 업무 폴더다. 팀원 누구나 필요할 때 Claude를 불러 아래 4가지 업무를 맡긴다.

| 업무 | 스킬 | 결과물 위치 |
|---|---|---|
| 주간보고 작성 | `/주간보고` | `보고서/` |
| 납기 지연·위험 추적 | `/납기추적` | `납기현황/` |
| 고객 메일 초안 작성 | `/메일초안` | `메일초안/` |
| 품질·클레임 추적 | `/클레임추적` | `품질/클레임_추적표.xlsx` |

## 공통 규칙 (모든 업무에 적용)

1. **권한: 읽고, 분석하고, 새 파일을 만드는 것까지만 한다.**
   - 메일 발송, 카톡 전송 같은 외부 발송은 하지 않는다. 초안 파일까지만 만든다.
   - 원본 자료(`생산일보/`, `생산계획_*.xlsx`, `품목마스터.csv`, `고객사_담당자.xlsx`, `메일함/`, `단톡방/`)는 수정하거나 덮어쓰지 않는다. 원본과 다른 점이 보이면 결과물에 적어서 사람이 고치게 한다.
   - **`수주대장.xlsx`는 예외로 업데이트할 수 있다.** 단, 아래 순서를 반드시 지킨다.
     1. 수정 전에 `백업/수주대장_MMDD_수정전.xlsx`로 복사한다(MMDD는 기준일). 같은 이름이 있으면 `_2`, `_3`을 붙인다.
     2. 근거 자료(카톡, 메일, 회의록, 현장메모 등)가 있는 내용만 수정한다. 근거가 불확실하면 수정하지 않고 `[확인]`으로 보고한다.
     3. 바꾼 칸마다 `변경이력` 시트에 한 줄씩 추가한다. 열은 일자, 수주번호, 바뀐 것, 변경 전, 변경 후, 출처(파일명과 날짜)이고, 서식은 윗줄과 맞춘다.
     4. 수주번호, 수량, 납기일 같은 계약 정보는 고객 확인과 팀장 승인이 자료로 확인될 때만 바꾼다. 진행상태와 비고는 근거가 있으면 바꾼다.
     5. 저장한 뒤 파일을 다시 열어 행 수와 변경 내용을 검산하고, 바꾼 내역을 표로 보고한다.
   - 같은 이름의 결과물이 이미 있으면 덮어쓰지 말고 파일명 끝에 `_v2`, `_v3`을 붙인다.
2. **판단하기 어려우면 `[확인]`이라고 적는다.** 추측으로 빈칸을 채우지 않는다. 자료가 없거나, 자료끼리 내용이 다르거나, 사람의 결정이 필요한 곳에는 해당 위치에 `[확인] 이유`를 적고, 마지막 답변에서 `[확인]` 항목을 모아서 보여준다.
3. **자료가 서로 다르면 카톡을 우선한다.** 우선순위는 단톡방 > 메일 > 회의록 > 수주대장·생산일보 순이다. 카톡을 따랐을 때는 "수주대장은 '출하준비', 카톡 10/12 기준 출하완료"처럼 차이를 함께 적는다.
4. **숫자는 파일에서 계산한다.** 수량, 달성률, 불량률, 경과일은 원본 파일로 계산하고, 결과물을 저장하기 전에 한 번 더 검산한다.
5. **기준일을 명시한다.** 사용자가 기준일을 말하지 않으면 오늘 날짜를 기준일로 쓰고, 결과물 첫머리에 "기준일: YYYY-MM-DD"를 적는다.

## 납기 판단 기준

미출하 수주(진행상태가 `출하완료`가 아닌 건)만 판단하고, 기준일에서 납기일을 뺀 값(D)으로 구분한다.

| 구분 | 조건 | 의미 |
|---|---|---|
| **지연** | 납기일 + 3일이 지나도 미출하 (D > +3) | 즉시 조치 필요 |
| **위험** | 납기 3일 전부터 납기 3일 후까지 미출하 (-3 ≤ D ≤ +3) | 집중 관리 |
| 정상 | 납기까지 3일보다 많이 남음 (D < -3) | — |
| 출하완료 | 진행상태 `출하완료`, 또는 카톡·출하 메일에 출하 기록이 있음 | — |

- 분할 납품 건(비고에 "분할 납품")은 잔량 기준으로 판단하고 비고를 그대로 옮긴다.
- 진행상태가 `수주확정`인데 위험·지연이면 생산 착수 여부를 `[확인]`으로 표시한다.

## 폴더 구조

```
생산관리_1016/
├── CLAUDE.md                 공통 지침 (이 파일)
├── .claude/skills/           업무별 스킬: 주간보고, 납기추적, 메일초안, 클레임추적
│
├── 수주대장.xlsx             ┐ 기준 자료 (수주대장만 백업 후 수정 가능, 나머지는 수정 금지)
├── 생산계획_{M}월.xlsx       │
├── 품목마스터.csv            │
├── 고객사_담당자.xlsx        ┘
│
├── 생산일보/                 ┐
├── 메일함/                   │
├── 단톡방/                   │ 매주 쌓이는 입력 자료 (원본, 수정 금지)
├── 회의록/                   │
├── 현장메모/                 │
├── 회의자료/                 ┘
│
├── 보고서/                   결과물: 주간보고 docx (최신 파일이 다음 주 양식)
├── 납기현황/                 결과물: 납기현황_MMDD.xlsx
├── 메일초안/                 결과물: 고객 메일 초안 txt
├── 품질/                     입력(클레임접수서 PDF) + 결과물(클레임_추적표.xlsx)
└── 백업/                     수주대장 수정 전 백업 (수주대장_MMDD_수정전.xlsx)
```

## 폴더와 파일 규칙 (매주 같은 폴더에 쌓인다)

파일명에 들어 있는 날짜로 이번 주 자료를 골라낸다. 이름 규칙이 다른 파일이 있으면 `[확인]`으로 알린다.

| 폴더/파일 | 파일명 규칙 | 내용 |
|---|---|---|
| `수주대장.xlsx` | 고정 | 시트 `수주대장`(수주번호, 고객사, 품번, 품명, 수량, 수주일, 납기일, 진행상태, 비고), 시트 `변경이력` |
| `생산계획_{M}월.xlsx` | 월별 | 라인·품번별 일 계획수량, 시트 `{M}월 특이일정`. 달성률이 90% 미만이면 미달 |
| `품목마스터.csv` | 고정 | 품번, 품명, 담당라인, 단가, 포장단위, 표준리드타임 |
| `고객사_담당자.xlsx` | 고정 | 고객사별 담당자, 직급, 이메일, 전화, 비고 |
| `생산일보/` | `{N}라인_생산일보_MMDD-MMDD.xlsx` 또는 `.csv` | 시스템에서 내려받은 파일. 열: 일자, 라인, 품번, 품명, 계획수량, 실적수량, 불량수량 |
| `메일함/` | `MMDD_발신처_제목.eml` | UTF-8 텍스트. 고객 문의와 출하팀 출하 보고 |
| `단톡방/` | `생산관리팀_카톡_MMDD-MMDD.txt` | 카톡 대화 내보내기 파일 |
| `회의록/` | `MMDD_주간생산회의.docx` | 결정사항 표: 항목, 담당, 기한 |
| `품질/` | `클레임접수서_CL-YYMM-NN_고객사.pdf` | 양식 QF-07 |
| `현장메모/` | `MMDD_현장메모.jpg` | 손글씨 메모 사진. 읽기 어려운 부분은 `[확인]` |
| `보고서/` | `주간보고_{M}월{W}주_MMDD-MMDD.docx` | 주간보고 결과물이자 다음 주 양식 |

## 팀 운영 원칙 (1006 회의록 기준)

- 주간보고는 매주 금요일 17:30까지 김도현 팀장에게 보낸다. 양식은 기존 주간보고와 똑같이 유지한다.
- 납기 변경은 라인 반장 확인 → 팀장 승인 → 담당자(박서준 대리) 회신 순서로 처리한다. 에이전트가 납기를 확정해서 약속하지 않는다.
- 가온모터스는 연간 물량 1위 고객이므로 납기 변경 요청을 우선 검토한다.

## 팀 구성

김도현 팀장 · 박서준 대리(주간보고, 고객 회신) · 이만수(1라인) · 정현우(2라인) · 최강호(3라인) · 오태식(4라인) · 한지연(품질) · 최민수(출하)

## 작업 환경

- 엑셀은 `openpyxl`, 워드는 `python-docx`, PDF는 Read 도구로 읽는다. 패키지가 없으면 `pip install openpyxl python-docx`로 설치한다.
- Windows 콘솔에서 한글이 깨지면 `PYTHONIOENCODING=utf-8`을 설정한다.
