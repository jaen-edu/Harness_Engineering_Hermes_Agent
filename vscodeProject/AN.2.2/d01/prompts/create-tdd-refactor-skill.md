아래 명세를 따르는 `.skills/tdd-refactor/SKILL.md` 파일을 생성해 주세요.

## Skill 명세

**이름**: tdd-refactor  
**목적**: 테스트가 PASSED인 상태를 유지하면서 구현 코드의 구조와 가독성을 개선합니다.

### 트리거 조건
- "리팩토링 해줘", "Refactor 단계 시작"
- "tdd-refactor Skill 사용해서"
- "코드 개선해줘" (테스트 파일이 존재하는 컨텍스트에서)
- "중복 제거해줘", "코드 정리해줘"

### 입력
- `<모듈명>.py`: 현재 PASSED 상태의 구현 파일 (필수)
- `test_<모듈명>.py`: 현재 통과 중인 테스트 파일 (필수)

### 출력
- `<모듈명>.py`: 개선된 구현 파일 (테스트는 여전히 PASSED 상태)

### 리팩토링 순서 (이 순서대로 진행)
1. **pytest 실행**: 현재 Green 상태 확인
2. **중복 코드 제거**: 동일한 로직이 두 곳 이상이면 함수로 추출
3. **함수명 개선**: 동사+명사 형식, 의도가 명확하게
4. **변수명 개선**: 단축어, 약어 제거 (`x` → `item_count`)
5. **타입 힌트 추가**: 모든 파라미터와 반환값
6. **매직 넘버 상수화**: 숫자/문자열 리터럴을 상수로 추출
7. **pytest 재실행**: 여전히 Green인지 확인

### 제약사항 (가장 중요)
- **새로운 기능을 추가하지 않습니다.**
- **`test_*.py` 파일을 수정하지 않습니다.**
- **각 변경 후 즉시 `pytest`를 실행합니다.**
- 테스트가 실패하면 **즉시 마지막 변경을 롤백**하고 원인을 설명합니다.
- 리팩토링 완료 후 `pytest --cov` 커버리지 리포트를 제공합니다.

### 완료 보고 형식
리팩토링 완료 시 다음을 보고합니다:
- 변경 사항 목록 (변경 전 → 변경 후)
- pytest 결과: `X passed`
- 커버리지 결과

### SKILL.md 완성 후 수행할 것
1. `.skills/tdd-refactor/SKILL.md` 경로에 파일 생성
2. 즉시 테스트: `tdd-green`으로 생성한 `calculator.py` 리팩토링
3. 리팩토링 전후 코드 diff를 직접 확인
4. `pytest test_calculator.py -v` → 여전히 모두 PASSED 확인
