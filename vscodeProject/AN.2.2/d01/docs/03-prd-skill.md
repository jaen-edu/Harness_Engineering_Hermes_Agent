## 1. PRD란 무엇인가?

> **PRD(Product Requirements Document, 제품 요구사항 문서)**  
> "무엇을 만들 것인가"를 이해관계자(개발자, 기획자, AI Agent)가 공통으로 참조할 수 있도록 구조화한 문서입니다.  
> 반대 개념: 구현 문서(Implementation Document)는 "어떻게 만들 것인가"를 다룹니다.  
> AI-Native 개발에서는 PRD가 모든 하위 Skills(TASK 분해, TDD)의 **단일 입력 원천(Single Source of Truth)**이 됩니다.

### PRD가 없으면 어떤 일이 생기나?

```
개발자: "로그인 기능 만들어줘"
AI: 어떤 로그인? JWT? OAuth? 이메일만? 소셜 로그인?
    비밀번호 찾기 포함? 2FA? ...
```

PRD가 있으면:
```
AI: PRD를 읽겠습니다.
    → 이메일+비밀번호 로그인, JWT 토큰, 만료 24h 확인
    → T01: 로그인 API, T02: 토큰 발급, T03: 만료 처리 생성
```

### PRD의 필수 섹션

| 섹션 | 목적 | AI에게 필요한 이유 |
|------|------|-------------------|
| 배경 및 문제 정의 | 왜 만드는가 | 불필요한 기능 방지 |
| 목표 | 무엇을 달성하는가 | 성공 기준 제공 |
| 사용자 스토리 | 누가 어떻게 사용하는가 | 테스트 시나리오 생성 |
| 기능 목록 | 무엇을 만드는가 | TASK 분해 입력 |
| 비기능 요구사항 | 어떻게 동작해야 하는가 | 구현 제약 설정 |
| 범위 밖 | 만들지 않는 것 | 과도한 구현 방지 |
| 성공 지표 | 완료 기준 | 검증 조건 제공 |

## 2. SKILL.md 구조

SKILL.md는 Copilot Agent에게 "이 작업을 이렇게 수행하라"고 지시하는 파일입니다.

### 필수 6가지 섹션

```markdown
# Skill: [이름]

## 트리거 조건
언제 이 Skill을 사용해야 하는가?
예: "PRD를 작성해달라는 요청이 들어올 때"

## 역할
이 Skill이 수행하는 작업을 한 줄로 요약합니다.

## 입력
- 필요한 파일 목록
- 필요한 정보 (없으면 사용자에게 물어볼 것)

## 출력
- 생성/수정할 파일
- 출력 형식 명세

## 제약사항
- 하지 말아야 할 것
- 포함하면 안 되는 내용

## 예시
입력 → 출력 예시 (짧게)
```

## 3. prd-writer Skill 설계

### 설계 결정 사항

| 결정 | 이유 |
|------|------|
| 출력을 `PRD.md`로 고정 | 다음 Skill(task-breakdown)이 파일명으로 찾기 때문 |
| 모호한 표현 금지 지침 포함 | AI가 "빠르게", "쉽게" 같은 표현을 쓰면 TASK로 변환 불가 |
| 사용자 확인 단계 포함 | PRD는 잘못되면 전체 작업이 틀어지므로 검토 필수 |

### 완성된 Skill 파일

`d01/lessons/.skills/prd-writer/SKILL.md` 참조

## 4. Agent Mode에서 Skill 호출 테스트

### 방법 1: 자연어 트리거

```
Todo 앱의 PRD를 작성해줘.
앱 이름: "SimpleTask"
핵심 기능: 할 일 추가, 완료 표시, 삭제
대상 사용자: 개인 생산성을 높이려는 직장인
```

### 방법 2: 프롬프트 파일 호출

Chat 입력창에서:
```
/prd-writer
project_name="SimpleTask"
feature_summary="할 일 추가, 완료 표시, 삭제"
target_users="개인 생산성을 높이려는 직장인"
```
변수를 채워 실행

### 확인 포인트

```
[ ] PRD.md가 프로젝트 루트에 생성되었는가?
[ ] 7개 필수 섹션이 모두 포함되었는가?
[ ] 사용자 스토리가 최소 3개 있는가?
[ ] "빠르게", "쉽게" 같은 모호한 표현이 없는가?
[ ] 성공 지표에 측정 가능한 수치가 있는가?
```
