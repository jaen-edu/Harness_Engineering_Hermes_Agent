# PRD: SimpleTask

## 1. 배경 및 문제 정의
터미널 환경에 익숙한 개발자는 작업 중 떠오르는 할 일을 빠르게 기록하고, 필요할 때 즉시 목록을 확인할 수 있는 도구가 필요합니다. 하지만 많은 할 일 관리 도구는 웹 또는 GUI 중심으로 설계되어 있어, 단순한 개인 작업 관리 용도로는 실행 과정이 번거롭고 기능이 과도한 경우가 많습니다.

SimpleTask는 터미널을 사용하는 개발자를 위한 간단한 Todo CLI 앱입니다. Python 3.12 기반으로 동작하며, 할 일 추가, 조회, 완료, 삭제 같은 핵심 기능만 제공해 가볍고 빠른 작업 관리 경험을 제공하는 것을 목표로 합니다.

## 2. 목표
- 개발자가 터미널에서 빠르게 할 일을 기록하고 관리할 수 있도록 한다.
- 명령어 기반 인터페이스를 통해 직관적이고 단순한 사용 경험을 제공한다.
- 핵심 기능인 추가, 조회, 완료, 삭제를 안정적으로 제공한다.

### 측정 가능한 성공 기준
- 사용자는 프로그램 실행 후 1분 이내에 첫 할 일을 추가할 수 있어야 한다.
- 핵심 기능 4가지는 각각 명확한 명령어 또는 옵션으로 실행 가능해야 한다.
- 주요 기능 테스트 통과율은 95% 이상이어야 한다.

## 3. 사용자 스토리
- 터미널을 자주 사용하는 개발자로서, 할 일을 빠르게 추가하고 싶다. 그래야 작업 흐름을 끊지 않고 바로 기록할 수 있다.
- 개발자로서, 현재 등록된 할 일을 한 번에 조회하고 싶다. 그래야 우선순위를 빠르게 확인할 수 있다.
- 사용자로서, 완료한 할 일은 완료 처리하고 불필요한 항목은 삭제하고 싶다. 그래야 목록을 최신 상태로 유지할 수 있다.

## 4. 기능 목록
| 우선순위 | 기능명 | 설명 |
|---------|--------|------|
| P0 | 할 일 추가 | 사용자는 명령어를 통해 새로운 할 일을 등록할 수 있다. |
| P0 | 할 일 조회 | 사용자는 현재 저장된 할 일 목록과 완료 상태를 확인할 수 있다. |
| P0 | 할 일 완료 표시 | 사용자는 특정 항목을 완료 상태로 변경할 수 있다. |
| P0 | 할 일 삭제 | 사용자는 특정 항목을 목록에서 삭제할 수 있다. |
| P1 | 입력 유효성 검사 | 빈 입력값 또는 존재하지 않는 항목 번호에 대해 명확한 오류 메시지를 제공해야 한다. |
| P1 | 데이터 유지 | 프로그램을 종료한 뒤 다시 실행해도 기존 할 일 목록이 유지되어야 한다. |

## 5. 비기능 요구사항
- 기술 스택: Python 3.12 기반 CLI 애플리케이션이어야 한다.
- 성능: 일반적인 로컬 개발 환경에서 각 명령은 1초 이내에 실행되어야 한다.
- 사용성: 명령어와 옵션 이름은 직관적이어야 하며, 도움말 기능을 제공해야 한다.
- 안정성: 잘못된 입력이 들어와도 프로그램이 비정상 종료되지 않아야 한다.
- 유지보수성: pytest를 이용한 테스트 작성이 가능하도록 구조화되어야 한다.

## 6. 범위 밖 (Out of Scope)
- 웹 또는 모바일 사용자 인터페이스
- 로그인 및 사용자 계정 기능
- 여러 사용자 간 데이터 공유
- 클라우드 동기화
- 태그, 우선순위, 알림 같은 고급 기능

## 7. 성공 지표
- 할 일 추가, 조회, 완료, 삭제 기능이 모두 정상 동작할 것
- 잘못된 입력에 대해 사용자가 이해할 수 있는 오류 메시지를 제공할 것
- 프로그램 재실행 후에도 데이터가 유지될 것
- 핵심 기능 관련 테스트가 95% 이상 통과할 것
